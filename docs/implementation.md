# HDB 本体与绿色 DLC 实现说明

2026-10-13。

## 设计来源与优先级

1. 本次明确指令：回归绿化前的原始城市经营构想，绿化作为 DLC，UI 用 GitHub 布局。
2. 今天找回的原始设计：城市模拟经营＋政策卡牌，自由建设；HDB 传统升级、Condo 招商、办公商业与熟食中心；历史模式和自由构筑模式。
3. 《HDB_Eco_Community_设计决策总档_2026-10-08.md》中标注的早期资产，以及其中已冻结的绿化规则，用于 DLC。
4. GitHub `EVENWaterOne/HDB_GAME` 的 `prototype/index.html` 作为 UI 布局与低多边形表现参考。

10 月组内版的 15 节点、5 群体、仪表盘失真、被遗忘者终局属于另一条设计线，没有未经决定地与本体合并。原文件的“只改既有 HDB、不增加容量”属于生态路线，未用来限制本体住房升级。

## 本次补充的实现参数

以下原本未定，属于可修改的 v1 实现选择：

- 9×8 地块，两条固定道路，南部 18 地块通过新区规划许可开放。
- 基础政治点 3，每回合回复；基础抽牌 5；手牌和牌库分离，种子驱动洗牌。
- 设施立即建成，居民按宜居度/容量逐回合入住；住房不直接拆除，非住宅重新规划成本 25。
- 宜居度直接显示，未强行采用尚未锁定的完全隐藏方案。
- 一般财政收入：公共运营拨款、市镇服务费、商业税费/设施收入；维护和持续政策支出扣除。不是将 HDB 全部建模为向居民收租。
- 所谓就业是通勤与周边岗位的简化代理，仅影响入住吸引力；未实现个人求职、劳动市场或 Frostpunk 类完整岗位调度。
- 设施建成 8 回合后，未维护服务效率降至 72%；维护牌恢复 3 回合。
- 历史模式 20 回合，固定 1964 住房产权、1968 住房融资、1989 融合政策等锚点；其他经济/卫生事件为虚构社区压力，未声称其游戏数值是历史事实。
- 4 个阶段目标，提前奖励和政治点上限提升，失败开放补救；这些是参考后来设计作出的本次完整实现补充。
- 财政连续 2 回合为负或低至 −200 进入财政危机；自由模式正常结算可继续 12 回合。
- 本地存档，3 个手动槽，离线导入/导出，最多撤销本回合 12 步，不能跨已结算回合。

## DLC 边界

核心引擎在 `dlc=false` 时排除绿色建筑、绿色政策、热季、暴雨与能源/碳排计算。默认本体目标只依赖住房、经济与公共生活；已验证一条无绿化的正常建设路线可完成全部历史目标。

单栋生态改造只影响本栋，不增加容量，不给邻居建筑光环。绿地按范围独立降低压力。居民制冷自动计算，没有地方政府开关空调的玩法。高温应急牌绑定各自事件 ID，未用者事件结束销毁。持续补贴的开支不随高温结束自动停止，免费结束牌保留在手中。

## 实现结构

所有建筑/卡牌/事件在 `data.js`；结算、卡牌生命周期、模式隔离和严格存档校验在 `engine.js`；前端使用同一套引擎而非独立的展示数值。失败操作返回原状态，提交后才保存。随机性由可恢复的 RNG 状态决定。

界面沿用原 GitHub 的布局与色彩：顶部资源/时间，左侧事件/目标，中间 3D 模型，右侧政策/顾问，底部政治点/牌堆/扇形手牌。补充主菜单、建筑目录、自由构筑、回合账本、图层、城市报告、存档、设置与终局。Three.js 损坏或 WebGL 不可用时使用同规则的等距 2D 回退图。

默认顾问仅为规则分析，已清楚标记。可连接真实模型，调用兼容 Chat Completions 的 HTTPS 接口。API Key 仅在内存中，游戏存档和持久配置不会保存它。发送局面摘要，不发送完整存档、用户资料。模型返回只作转义后的文本显示，不可执行建设或数值修改。

## 验证与限制

运行 `npm run check` 和 `npm test`。测试包含错误操作事务性、HDB/Condo、不同摆放的设施覆盖、持续政策及免费停止、负财政恢复、时代解锁、本体/DLC 隔离、热季过期牌、任务补救、自由延长、撤销、存档/RNG、一组种子下的混合行动模拟、无绿化全目标路线，以及真正 UI 事件处理器的桌面/手机/牌组/终局/模型模拟响应流程。

DOM harness 只验证初始化与事件/状态流，不验证真实 CSS 布局、WebGL 渲染和鼠标拖拽视觉。当前环境未提供 Sites 所要求的浏览器 QA 能力，因此未启动浏览器预览。模型测试使用模拟响应，没有消耗真实服务，也未声称任何外部模型已经连接。后续应在手机和桌面进行视觉试玩，并进行多人平衡测试。
